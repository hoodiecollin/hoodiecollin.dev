# hoodiecollin.dev

Personal site and writing for Collin Kokotas. A static, MDX-driven site with a
design system of its own — no CMS, no server at runtime.

## Stack

Next.js 16 (app router) · React 19 · TypeScript (strict) · Tailwind v4 (CSS-first)
· shadcn/ui (`radix-nova`) · jotai + next-themes · **bun**. Posts are MDX compiled
at build time with `next-mdx-remote/rsc`; code is highlighted by Shiki with a dual
light/dark theme. Search is a client-side ⌘K palette over a prebuilt static index.
The green house accent lives in the oklch design tokens (`app/globals.css`).

## Develop (from the repo root — no `cd` needed)

```bash
bun install       # install deps
bun dev           # dev server on http://localhost:3000
bun typecheck     # tsc --noEmit
bun run build     # static export → ./out (NODE_ENV=production)
bun run clean     # drop .next / out / generated search index
```

The production `build` runs `output: "export"`, producing a fully static `out/`
that can be hosted anywhere (Cloudflare Pages, GitHub Pages, Vercel, an object
store). `bun dev` runs as a normal Node server so route handlers work locally.

## Deploy

Deployed to Vercel as a static export. `vercel.json` carries the platform-level
config (applied at the edge, since `output: "export"` ignores `next.config`
`headers()`):

- **Security headers** on every route (`X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`, HSTS).
- **Immutable caching** (`max-age=31536000, immutable`) for hashed `/_next/static`
  assets.
- A same-origin **`/relay` reverse-proxy** to PostHog US, so analytics ingestion
  isn't blocked by `*.posthog.com` ad-block filter lists.

## Analytics

Two lightweight, privacy-conscious layers, both **inert in local dev**:

- **Vercel Web Analytics** — `<Analytics />` in `app/layout.tsx`; zero-config on
  Vercel.
- **PostHog** — initialised in `app/providers.tsx` only when
  `NEXT_PUBLIC_POSTHOG_KEY` is set (see `.env.example`). Set it in the Vercel
  project env for production/preview; pageviews are captured manually for
  app-router SPA navigations.

## Content

- **Posts** are flat MDX files under `content/writing/*.mdx`. Frontmatter:

  ```yaml
  ---
  title: "Post title"
  description: "One-line summary (shown in listings + search)."
  date: "2026-07-27" # ISO; drives sort order
  draft: false # optional — hidden from listings/search in production
  ---
  ```

  Add a file and it appears in the listing, the routes, and the search index —
  no registration step. MDX can use the `<Callout>` component and standard prose.
- **Search index** (`public/search-index.json`) is generated by the `prebuild`
  step (`scripts/build-search-index.ts`) and is gitignored — never edit by hand.

## Structure

```
app/                 routes (landing, /writing, /writing/[slug]) + layout/globals
components/           chrome (header/footer/nav/search), mdx/, ui/ (shadcn)
content/writing/      MDX posts
lib/                  site config, mdx loader, search, toc, token/util helpers
scripts/              build-search-index.ts (prebuild)
```
